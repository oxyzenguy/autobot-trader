# 주문 체결 안전성 보완 기록

검토 기준: 외부 코드 검증 보고서가 지적한 `e588b07` 시점의 실전 주문·상태 저장 결함을 현재 코드에서 다시 확인했다.

## 반영한 항목

| 보고서 항목 | 처리 |
| --- | --- |
| 시장가 주문 UUID만 확인 | 주문 UUID로 상세 상태를 조회하고, `done`·실제 체결수량·거래별 체결가가 확인돼야만 장부를 갱신하도록 변경 |
| 장중 잔고 차이와 추정 수량 | 제거. `executed_volume`과 `trades[].funds`에서 실제 수량과 가중 평균 체결가를 사용 |
| 시장가 매도 부분체결 | 포지션·차수 장부를 바꾸지 않고 `trading_halted`와 주문 UUID를 상태에 저장해 재조정 전 추가 주문을 차단 |
| 지정가 주문 응답 무시 | UUID가 없는 응답은 실패로 처리하고 주문 등록 성공 메시지를 내지 않음 |
| 취소 요청 후 즉시 재주문 | 취소 뒤 주문 상태가 `cancel`인지 확인. `done`·대기·오류면 거래를 중단 |
| 상태 파일 직접 덮어쓰기 | 같은 디렉터리의 임시 파일에 flush·fsync한 뒤 `os.replace()`로 원자 교체 |
| 체결 로그에 주문 UUID 누락 | 확정 시장가 체결을 `trade_history.db`에 기록할 때 주문 UUID도 저장 |

## 안전 동작

- 시장가 매수의 실제 체결수량이 요청액보다 작아도, 거래소가 `done`으로 확정한 실제 수량과 평균 체결가만 기록한다.
- 시장가 매도가 요청 수량보다 적게 체결되거나 주문이 대기·거부 상태면 거래를 중단한다. 이 상태에서 자동 재주문하거나 남은 포지션을 0으로 기록하지 않는다.
- 중단 상태는 상태 JSON의 `trading_halted`, `halt_reason`, `pending_order_uuid`에 남는다. 거래소 주문·잔고를 확인하고 장부를 재조정한 뒤에만 운영자가 중단 상태를 해제해야 한다.

## 검증 결과

`autotrade-order-qa`는 가짜 거래소를 이용해 다음을 확인했다.

- 완료된 시장가 매수: 실제 `executed_volume`, 거래별 `funds` 가중 평균 가격, 수수료를 반환
- 대기 시장가 주문: `PENDING` 반환, 장부 갱신 없음
- 부분 체결 시장가 매도: `PARTIAL` 반환, 거래 중단 경로 사용
- 지정가 주문 거부와 취소 확정 상태: 각각 실패·성공으로 식별
- 상태 저장: 유효 JSON으로 재로딩되고 임시 파일이 남지 않음

## 별도 후속 과제

- OHLC 백테스트의 같은 봉 내 체결 순서·슬리피지·부분체결 가정은 성과 평가 정책을 바꾸므로 이 주문 안전성 수정에 섞지 않았다. 별도 백테스트 정책과 기준 성과를 합의한 뒤 변경한다.
- 자동 재조정은 수동매매·보호수량과의 구분 규칙이 필요하다. 현재는 불확실한 주문 상태에서 안전하게 중단하고 운영자 확인을 요구한다.
